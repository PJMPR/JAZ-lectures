01 // KLASA ANONIMOWA

Obiekt bez nazwy klasy

Klasa anonimowa jednocześnie definiuje klasę i tworzy jej jedyną instancję. Przydaje się, gdy implementacja jest lokalna i krótka.

new InterfaceName() { ... }ciało klasy może implementować metody i posiadać pola

02 // INTERFEJS FUNKCYJNY

Jedna metoda abstrakcyjna

Operation.java
@FunctionalInterface
interface Operation {
    int apply(int left, int right);
}

Interfejs funkcyjny ma dokładnie jedną metodę abstrakcyjną. Lambda dostarcza implementację tej metody.

@FunctionalInterface: adnotacja nie jest wymagana, ale kompilator pilnuje dzięki niej kontraktu.

Metody default, static oraz metody odziedziczone z Object nie zwiększają liczby metod abstrakcyjnych.

PRZYKŁAD 02 // KONTRAKT

Który interfejs jest funkcyjny?

A: void run()

Jedna metoda abstrakcyjna. Lambda pasuje.

B: test() + default log()

Metoda domyślna nie łamie kontraktu.

C: start() + stop()

Dwie metody abstrakcyjne. Lambda nie określi, którą implementuje.

Pytanie do sali Czy interfejs bez adnotacji może być funkcyjny?

PRZYKŁAD 03 // REDUKCJA SKŁADNI

Od klasy anonimowej do lambdy

Before.java
Operation add = new Operation() {
    @Override
    public int apply(int a, int b) {
        return a + b;
    }
};
After.java

int result = add.apply(2, 3);
WYNIK

Ten sam kontrakt

Typ zmiennej wskazuje interfejs, a więc także parametry i typ wyniku lambdy.

04 // TARGET TYPING

Lambda potrzebuje kontekstu

Lambda sama nie ma nazwanego typu. Kompilator interpretuje ją jako implementację interfejsu wynikającego z przypisania, argumentu metody lub zwracanego typu.

Nie zadziała: var action = () -> "OK"; nie podaje docelowego interfejsu.
Supplier<String> first = () -> "OK";

execute(() -> System.out.println("Go"));

static Predicate<String> rule() {
    return text -> !text.isBlank();
}
PRZYKŁAD 04 // CAPTURE

Lambda korzysta z otoczenia

Capture.java
int minimum = 5;
Predicate<String> longEnough =
    text -> text.length() >= minimum;

System.out.println(longEnough.test("lambda"));

// minimum = 8; // odebrałoby effective final
OGRANICZENIE

Effectively final

  1. Lambda może odczytać zmienną lokalną.
  2. Zmienna nie może później otrzymać nowej wartości.
  3. Pola obiektu nie podlegają temu ograniczeniu.

06 // JAVA.UTIL.FUNCTION

Predicate<T> testuje warunek

T -> booleanboolean test(T value)

Predicate służy do filtrowania, walidacji i wyszukiwania. Można łączyć warunki metodami and, or oraz negate.

Predicate<String> notBlank =
    text -> !text.isBlank();
Predicate<String> shortText =
    text -> text.length() <= 20;

Predicate<String> valid =
    notBlank.and(shortText);

valid.test("Java"); // true
PRZYKŁAD 06 // FUNCTION

Function<T, R> zmienia wartość

Functions.java
Function<String, String> clean = String::trim;
Function<String, Integer> length = String::length;

Function<String, Integer> cleanLength =
    clean.andThen(length);

int result = cleanLength.apply(" Java ");
// 4
SYGNATURA

T -> R

  1. T opisuje argument.
  2. R opisuje wynik.
  3. andThen przekazuje wynik pierwszej funkcji do drugiej.
07 // WEJŚCIE I WYJŚCIE

Consumer i Supplier

Consumer<T>: T -> voidaccept(T value) wykonuje operację
Consumer<String> log = System.out::println;
log.accept("gotowe");
Supplier<T>: () -> Tget() dostarcza wartość
Supplier<UUID> id = UUID::randomUUID;
UUID next = id.get();
PRZYKŁAD 07 // OPERATORY

Gdy argument i wynik mają ten sam typ

UnaryOperator<String> normalize =
    text -> text.trim().toLowerCase();

BinaryOperator<Integer> maximum =
    Integer::max;

normalize.apply(" JAVA "); // java
maximum.apply(7, 12);   // 12
SPECJALIZACJA

Mniej parametrów typów

UnaryOperator<T> specjalizuje Function<T,T>, a BinaryOperator<T> specjalizuje BiFunction<T,T,T>.

Wybieraj najbardziej precyzyjny standardowy interfejs.
08 // DWA ARGUMENTY

Rodzina interfejsów Bi...

BiFunction<T,U,R>

Dwa argumenty mogą mieć różne typy, wynik ma typ R.

BiPredicate<T,U>

Sprawdza warunek zależny od dwóch wartości.

BiConsumer<T,U>

Przyjmuje dwie wartości i nie zwraca wyniku.

BiFunction<String, Integer, String> repeat = String::repeat;
BiConsumer<String, Integer> printEntry = (key, value) -> System.out.println(key + ": " + value);
PRZYKŁAD 08 // METHOD REFERENCE

Odwołanie do istniejącej metody

text -> text.trim()       // lambda
String::trim             // metoda instancji

value -> Integer.parseInt(value)
Integer::parseInt        // metoda statyczna

() -> new ArrayList<>()
ArrayList::new           // konstruktor

value -> printer.print(value)
printer::print           // konkretny obiekt
REGUŁA

Ta sama sygnatura

Odwołanie do metody działa, gdy jej parametry i wynik pasują do metody interfejsu funkcyjnego.

Jeśli lambda dodaje logikę, nazwę parametru lub ułatwia czytanie, pozostaw lambdę.

09 // SPECJALIZACJE

Mniej autoboxingu

Java dostarcza odmiany dla int, long i double. Unikają tworzenia obiektów opakowujących w intensywnie wykonywanym kodzie.

IntPredicate int → booleanIntFunction<R> int → RToIntFunction<T> T → intIntConsumer int → void
IntPredicate even = value -> value % 2 == 0;
ToIntFunction<String> length = String::length;
IntUnaryOperator square = value -> value * value;

even.test(8);       // bez Integer
length.applyAsInt("Java");
square.applyAsInt(5);
PRZYKŁAD 09 // STREAM API

Potok operacji

Pipeline.java
List<String> result = names.stream()
    .filter(name -> name.length() >= 4)
    .map(String::toUpperCase)
    .sorted()
    .toList();
PRZEPŁYW

Każdy etap ma inny kontrakt

  1. filter używa Predicate.
  2. map używa Function.
  3. sorted może użyć Comparator.

Operacje pośrednie są leniwe. Terminalne toList uruchamia potok.

10 // WYJĄTKI SPRAWDZANE

Sygnatura interfejsu wyznacza wyjątki

Standardowe interfejsy funkcyjne zwykle nie deklarują wyjątków checked. Lambda nie może więc swobodnie wywołać metody, która taki wyjątek zgłasza.

Rozwiązania: obsłuż wyjątek w lambdzie, opakuj go w wyjątek runtime albo zdefiniuj własny interfejs z throws.
@FunctionalInterface
interface CheckedFunction<T, R> {
    R apply(T value) throws IOException;
}

CheckedFunction<Path, String> read =
    Files::readString;
CHECKPOINT // DOBÓR INTERFEJSU

Co pasuje do sygnatury?

1. Walidacja

Przyjmuje zamówienie i zwraca boolean.

Predicate<Order>

2. Fabryka

Nie przyjmuje argumentu i tworzy identyfikator.

Supplier<UUID>

3. Mapowanie

Zamienia User na UserDto.

Function<User, UserDto>
LAMBDA = implementacja jednej metody + typ docelowy + zwięzłe przekazanie zachowania
