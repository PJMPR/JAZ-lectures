PRZYKŁAD 00 // KOD NIE ZNA TYPU

Inspektor dowolnego obiektu

static void inspect(Object value) {
    Class<?> type = value.getClass();
    System.out.println(type.getName());

    for (Method method : type.getDeclaredMethods()) {
        System.out.println(method.getName());
    }
}
RÓŻNICA

Informacja dostępna w runtime

Kompilator widzi tylko Object. Uruchomiony program może jednak poznać rzeczywistą klasę przekazanej wartości i zbadać jej definicję.

01 // MODEL

Refleksja opisuje kod za pomocą obiektów

Class<?>

Typ

Nazwa, pakiet, modyfikatory, nadklasa i interfejsy.

Member

Elementy

Field, Constructor i Method opisują składniki klasy.

java.lang.reflect

API

Standardowe typy pozwalają przeglądać i wykorzystywać tę strukturę.

Metadane: refleksja pracuje na opisie programu, a nie na tekście pliku źródłowego.
02 // TRZY DROGI

Jak uzyskać obiekt Class?

ClassObjects.java
Class<String> fromLiteral = String.class;
Class<? extends String> fromObject = "JAZ".getClass();
Class<?> fromName = Class.forName("java.lang.String");

System.out.println(fromLiteral == fromObject); // true
.class gdy typ jest znany w kodziegetClass() gdy mamy obiektforName gdy nazwę poznajemy w runtime
03 // TOŻSAMOŚĆ TYPU

Jedna załadowana klasa — jeden obiekt Class

Literał klasy nie tworzy instancji badanego typu. Reprezentuje definicję załadowaną przez konkretny class loader.

Ważne: pełna tożsamość klasy zależy od jej nazwy oraz loadera, który ją załadował.
Class<?> type = ArrayList.class;

type.getName();          // java.util.ArrayList
type.getSimpleName();    // ArrayList
type.getPackageName();   // java.util
type.getClassLoader();
04 // KLASYFIKACJA

Nie każdy Class opisuje zwykłą klasę

type.isInterface();
type.isEnum();
type.isRecord();
type.isArray();
type.isPrimitive();
type.isSynthetic();
PRZYKŁADY
  1. Runnable.class — interfejs
  2. Thread.State.class — enum
  3. User.class — rekord lub klasa
  4. String[].class — tablica
  5. int.class — typ prymitywny
05 // MODIFIERS

Modyfikatory są zakodowane jako maska bitowa

int modifiers = type.getModifiers();

Modifier.isPublic(modifiers);
Modifier.isAbstract(modifiers);
Modifier.isFinal(modifiers);

String text = Modifier.toString(modifiers);

Ta sama klasa Modifier interpretuje modyfikatory klas i ich elementów. Nie porównujemy liczby z „magiczną” wartością.

PUBLIC | FINAL → intkażdy bit reprezentuje osobną cechę
06 // RELACJE

Nadklasa, interfejsy i zgodność typów

Class<?> type = ArrayList.class;

Class<?> parent = type.getSuperclass();
Class<?>[] interfaces = type.getInterfaces();

List.class.isAssignableFrom(type); // true
type.isInstance(new ArrayList<>()); // true
CZYTAJ JAK PYTANIE

A.isAssignableFrom(B)

Czy wartość typu B można przypisać do zmiennej typu A?

Kierunek jest częstym źródłem pomyłek.

07 // DECLARED VS PUBLIC

„Zadeklarowane tutaj” to nie to samo co „publicznie dostępne”

getDeclared…()

  • elementy zapisane bezpośrednio w klasie,
  • wszystkie poziomy dostępu,
  • bez elementów odziedziczonych.

get…()

  • tylko elementy publiczne,
  • łącznie z odziedziczonymi,
  • zgodnie z publicznym API typu.
DOBÓR METODY zależy od pytania, które zadaje inspektor.
08 // FIELD

Badanie pól klasy

for (Field field : type.getDeclaredFields()) {
    System.out.printf("%s %s %s%n",
        Modifier.toString(field.getModifiers()),
        field.getType().getSimpleName(),
        field.getName());
}
FIELD OPISUJE
  1. nazwę pola,
  2. typ deklarowany,
  3. modyfikatory,
  4. klasę deklarującą,
  5. wartość dla wskazanej instancji.
09 // ODCZYT

Opis pola i wartość pola to dwie różne rzeczy

Product product = new Product("K-1", 42);
Field field = Product.class.getDeclaredField("stock");

if (field.trySetAccessible()) {
    Object value = field.get(product);
    System.out.println(value); // 42
}

Field reprezentuje element definicji. Dopiero get(product) odczytuje go z konkretnego obiektu.

Hermetyzacja: wymuszanie dostępu zwiększa sprzężenie i może zostać ograniczone przez system modułów.
10 // CONSTRUCTOR

Konstruktor można znaleźć po typach parametrów

Constructor<Product> constructor =
    Product.class.getDeclaredConstructor(
        String.class, int.class);

Product product = constructor.newInstance("K-2", 10);
DOPASOWANIE

Sygnatura musi być dokładna

Kolejność i typy argumentów mają znaczenie. int.class i Integer.class opisują inne sygnatury.

11 // METHOD

Metodę identyfikuje nazwa i lista parametrów

Method method = Product.class.getDeclaredMethod(
    "reserve", int.class);

Object result = method.invoke(product, 3);
System.out.println(result);
METHOD OPISUJE
  1. typ zwracany i nazwę,
  2. typy parametrów i wyjątków,
  3. modyfikatory i klasę deklarującą,
  4. możliwość wywołania dla instancji.
12 // INVOKE

invoke przesuwa część kontroli do runtime

target

Odbiorca

Instancja dla metody obiektowej; null dla metody statycznej.

Object...

Argumenty

Niepoprawna liczba lub typ zostaną wykryte dopiero podczas wykonania.

Object

Wynik

Typ wyniku trzeba sprawdzić lub jawnie rzutować.

Trade-off: elastyczność rośnie, ale tracimy część pomocy kompilatora.
13 // OBSŁUGA BŁĘDÓW

Dwa miejsca, w których może nie wyjść

WYSZUKIWANIE
try {
    Method m = type.getDeclaredMethod("run");
} catch (NoSuchMethodException e) {
    // definicja nie pasuje
}
WYKONANIE
try {
    m.invoke(target);
} catch (InvocationTargetException e) {
    Throwable cause = e.getCause();
}
InvocationTargetException opakowuje wyjątek rzucony przez wywołaną metodę.
14 // PARAMETER

Nazwy parametrów mogą nie trafić do bytecode

for (Parameter parameter : method.getParameters()) {
    System.out.println(parameter.getName());
    System.out.println(parameter.getType());
    System.out.println(parameter.isNamePresent());
}

Bez opcji kompilatora -parameters program może zobaczyć nazwy techniczne, np. arg0. Typy i kolejność parametrów nadal są dostępne.

Maven: ustaw <parameters>true</parameters>, jeśli nazwy są częścią kontraktu narzędzia.
15 // TYPE API

Typ surowy i deklaracja generyczna

Field field = Catalog.class.getDeclaredField("products");

Class<?> raw = field.getType();
Type generic = field.getGenericType();

// raw: interface java.util.List
// generic: java.util.List<Product>
ERASURE

Nie wszystko znika

Instancja listy nie pamięta swojego argumentu typu, ale deklaracja pola lub metody może zachować podpis generyczny w pliku klasy.

16 // RODZINA TYPE

Type ma kilka reprezentacji

Class

Konkretny typ

String, int albo typ tablicowy.

ParameterizedType

Typ z argumentami

Na przykład Map<String, Product>.

TypeVariable

Zmienna typu

Na przykład T w deklaracji Box<T>.

if (generic instanceof ParameterizedType p) {
    System.out.println(Arrays.toString(p.getActualTypeArguments()));
}
17 // RECORD COMPONENT

Rekord udostępnia swój model danych

if (type.isRecord()) {
    for (RecordComponent component
            : type.getRecordComponents()) {
        System.out.println(component.getName());
        System.out.println(component.getType());
        System.out.println(component.getAccessor());
    }
}
SEMANTYKA

RecordComponent opisuje składnik nagłówka rekordu. Jest lepszym modelem rekordu niż traktowanie go wyłącznie jako zbioru pól.

18 // ARRAY

Tablice też można obsłużyć bez znajomości typu elementu

Object values = new int[] { 10, 20, 30 };

Class<?> type = values.getClass();
System.out.println(type.getComponentType());

int length = Array.getLength(values);
Object first = Array.get(values, 0);

java.lang.reflect.Array działa zarówno dla tablic obiektów, jak i tablic typów prymitywnych.

Praktyka: przydatne w ogólnych serializerach, mapperach i narzędziach diagnostycznych.
19 // GDZIE TO DZIAŁA

Refleksja jest mechanizmem infrastruktury

framework

Tworzenie obiektów

Kontenery i fabryki odkrywają konstruktory oraz zależności.

mapping

Mapowanie danych

Biblioteki wiążą nazwy i typy danych ze strukturą obiektu.

testing

Narzędzia

20 // TRADE-OFF

Elastyczność ma cenę

Ryzyka

  • błędy przesunięte z kompilacji do runtime,
  • słabsza nawigacja i refaktoryzacja w IDE,
  • naruszenie granic hermetyzacji,
  • dodatkowy koszt wyszukania i wywołania.

Ogranicz koszt

  • waliduj kontrakt na starcie aplikacji,
  • buforuj znalezione metadane,
  • zamknij refleksję w małym komponencie,
  • preferuj zwykłe wywołania w kodzie domenowym.

    }

CHECKPOINT // DOBÓR API

Która operacja pasuje?

1. Rzeczywisty typ obiektu

Mamy wartość jako Object.

value.getClass()

2. Prywatne pola tej klasy

Bez pól odziedziczonych.

getDeclaredFields()

3. Publiczna metoda

Także odziedziczona.

getMethod(name, types)

PRZYKŁAD FINAŁOWY // MINI FRAMEWORK

Uruchom metodę wskazaną konfiguracją

String className = "pl.pjatk.jaz.reflection.Task";
String methodName = "execute";

Class<?> type = Class.forName(className);
Object task = type.getDeclaredConstructor().newInstance();
Method method = type.getMethod(methodName);
method.invoke(task);
PRZEŚLEDŹ ETAPY
  1. załaduj definicję po nazwie,
  2. sprawdź wymagany kontrakt,
  3. utwórz instancję,
  4. znajdź i wywołaj metodę,
  5. obsłuż przyczynę ewentualnego błędu.

W produkcji każdy etap powinien zgłosić czytelny błąd konfiguracji.
