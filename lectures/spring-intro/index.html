04 // ROZDZIELENIE POJĘĆ

Spring Framework dostarcza mechanizmy, Spring Boot wybiera rozsądne ustawienia startowe

Spring Framework

  • definiuje kontener IoC i API aplikacji,
  • udostępnia moduły web, data i testing,
  • pozwala jawnie skonfigurować każdy element.

Spring Boot

  • dobiera zależności przez startery,
  • konfiguruje aplikację na podstawie classpath,
  • upraszcza uruchomienie i obserwację aplikacji.

07 // DEPENDENCY INJECTION

DI jest konkretną realizacją zasady IoC

constructor

Konstruktor

Pełny kontrakt obiektu, niezmienność i proste testowanie. Preferowany wariant.

setter

Setter

Przydatny dla zależności opcjonalnych lub rekonfigurowalnych.

field

Pole

Krótki zapis, ale ukrywa kontrakt i utrudnia testowanie bez kontenera.

08 // KONTRAKT KLASY

Konstruktor ujawnia wymagane zależności

OrderService.java
public final class OrderService {
    private final OrderRepository repository;
    private final NotificationGateway notifications;

    public OrderService(
            OrderRepository repository,
            NotificationGateway notifications) {
        this.repository = repository;
        this.notifications = notifications;
    }
}
BEZ ADNOTACJI

Jeden konstruktor wystarcza

Spring potrafi wybrać jedyny konstruktor bez @Autowired. Klasa pozostaje zwykłą klasą Java i można ją utworzyć w teście.

09 // SŁOWNIK SPRINGA

Bean to obiekt zarządzany przez kontener Spring

  • ma definicję znaną kontenerowi,
  • może otrzymywać inne beany jako zależności,
  • ma nazwę, typ, scope i cykl życia,
  • może być przetwarzany przez infrastrukturę Springa.
WAŻNE ROZRÓŻNIENIE

Każdy bean jest obiektem

Nie każdy obiekt utworzony operatorem new jest beanem. Kontener zarządza wyłącznie instancjami, które poznał przez konfigurację.

11 // JAWNE DEFINICJE

@Configuration i @Bean opisują graf

ExplicitConfiguration.java
@Configuration
class ExplicitConfiguration {
    @Bean
    OrderRepository repository() {
        return new InMemoryOrderRepository();
    }

    @Bean
    OrderService orderService(
            OrderRepository repository,
            NotificationGateway notifications) {
        return new OrderService(repository, notifications);
    }
}
PARAMETRY METODY

Kontener odnajduje beany pasujące typem do parametrów i przekazuje je przy wywołaniu metody @Bean.

12 // BOOTSTRAP BEZ BOOTA

Kontener można uruchomić bez Spring Boot

App.java
try (var context =
        new AnnotationConfigApplicationContext(
            ExplicitConfiguration.class)) {

    OrderService service =
        context.getBean(OrderService.class);

    service.placeOrder("SPRING-101");
}
CEL DEMONSTRACJI

Widzimy granicę kontenera

getBean pobiera punkt wejścia. Wewnątrz logiki biznesowej zależności trafiają przez konstruktor, bez odwołań do API Springa.

13 // COMPONENT SCAN

Spring może wykrywać klasy oznaczone stereotypami

Warstwa aplikacji
@Component
class PricingService { ... }

@Repository
class JdbcOrderRepository { ... }

@Configuration
@ComponentScan("pl.pjatk.jaz")
class ScanConfiguration { }

@Component jest ogólnym stereotypem. @Service, @Repository i @Controller opisują rolę komponentu.

Granica skanowania: pakiet startowy wpływa na to, które klasy kontener zobaczy.

17 // DLACZEGO DI

Jawne zależności upraszczają zmianę implementacji i testy

Kod aplikacji

  • zależy od interfejsów i kontraktów,
  • nie zna sposobu tworzenia infrastruktury,
  • może otrzymać inną implementację przez konfigurację.

Test jednostkowy

  • tworzy obiekt bez kontenera,
  • podstawia lekkie fake lub mock,
  • weryfikuje zachowanie jednej klasy.

CHECKPOINT // FUNDAMENTY

Co zrobi kontener?

1. Jeden konstruktor

Czy potrzebuje @Autowired?

Nie. Spring wybierze jedyny konstruktor.

2. Dwa repozytoria

Oba implementują ten sam interfejs.

Trzeba wskazać wybór, np. przez @Primary lub @Qualifier.

3. Obiekt przez new

Czy automatycznie jest beanem?

Nie. Kontener musi poznać jego definicję.
