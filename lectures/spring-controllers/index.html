02 // GRANICA APLIKACJI

Kontroler tłumaczy HTTP na wywołanie logiki aplikacji

Odpowiedzialność kontrolera

  • odczytać dane z żądania,
  • sprawdzić kontrakt wejściowy,
  • wywołać serwis i zbudować odpowiedź.

Poza kontrolerem

  • reguły biznesowe i transakcje,
  • zapytania do bazy danych,
  • integracje z innymi systemami.
Cienki kontroler: kod HTTP pozostaje na brzegu, a logika biznesowa trafia do serwisu.

05 // CO MOŻNA USTAWIĆ

Najczęstsze ustawienia aplikacji internetowej

server.*

Serwer

Port, adres nasłuchu, context path, kompresja, HTTP/2, SSL i limity połączeń.

spring.mvc.*

Spring MVC

Problem Details, formaty dat, obsługa statycznych zasobów i zachowanie mapowania.

logging.*

Diagnostyka

Poziomy logowania, format komunikatów i szczegóły obsługi żądań.

Środowiska: wartości mogą pochodzić z pliku, zmiennych środowiskowych, profilu lub argumentów uruchomienia.
06 // PRODUKCJA

Rozsądne ustawienia

  • server.error.include-stacktrace=never,
  • server.error.include-message=never,
  • sekrety poza repozytorium.

Obserwowalność

  • szczegóły błędu zapisuj w logach,
  • klientowi zwracaj stabilny kontrakt,
  • identyfikator pozwala połączyć błąd z logiem.
07 // KLASA KONTROLERA

@RestController oznacza komponent zwracający body odpowiedzi

BookController.java
@RestController
@RequestMapping("/api/books")
class BookController {
    private final BookService service;
    BookController(BookService service) {
        this.service = service;
    }
}

@RestController łączy semantykę @Controller i @ResponseBody.

08 // DWA STYLE

@Controller wybiera widok, @RestController zapisuje dane do body

@Controller

  • typowy dla MVC z szablonami HTML,
  • zwrócony String może być nazwą widoku,
  • Model przenosi dane do widoku.

@RestController

  • typowy dla API HTTP,
  • obiekt jest serializowany do JSON,
  • status i nagłówki można ustawić osobno.
09 // ADRES BAZOWY

@RequestMapping opisuje warunki dopasowania żądania

path

Ścieżka

/api/books, zmienne i wzorce URL.

method

Metoda HTTP

GET, POST, PUT, PATCH albo DELETE.

consumes / produces

Reprezentacja

Typ danych wejścia i typ odpowiedzi, na przykład JSON.

Kompozycja: mapowanie na klasie daje prefiks, a mapowanie na metodzie dopisuje resztę ścieżki.
10 // ADNOTACJE SKRÓTOWE

Adnotacja metody wskazuje znaczenie endpointu

@GetMapping

Odczyt

Pobranie zasobu lub kolekcji bez zmiany stanu.

@PostMapping

Utworzenie

Nowy zasób lub operacja, której wynik identyfikuje serwer.

@PutMapping

Zastąpienie

Pełny nowy stan zasobu pod znanym adresem.

@PatchMapping

Częściowa zmiana

Aktualizacja wybranych pól.

@DeleteMapping

Usunięcie

Usunięcie zasobu wskazanego przez URL.

@RequestMapping

Pełna kontrola

Wspólny prefiks albo dodatkowe warunki dopasowania.

11 // KOLEKCJA

GET może łączyć ścieżkę z opcjonalnym filtrem query

BookController.java
@GetMapping
List<BookResponse> findAll(
        @RequestParam(required = false) String author,
        @RequestParam(defaultValue = "20") int limit) {
    return service.findAll(author, limit);
}

GET /api/books?author=Le%20Guin&limit=10 zawiera dwa parametry query.

12 // TOŻSAMOŚĆ ZASOBU

@PathVariable pobiera wartość z segmentu ścieżki

BookController.java
@GetMapping("/{id}")
BookResponse findOne(
        @PathVariable long id) {
    return service.findOne(id);
}
DOPASOWANIE

/api/books/42

Spring przechwytuje tekst 42 i konwertuje go do long. Błędny format kończy się odpowiedzią 400.

13 // PROJEKT URL

Ścieżka wskazuje zasób, query modyfikuje sposób odczytu

Path variable

/books/42

  • część tożsamości zasobu,
  • zwykle wymagana,
  • wpływa na dopasowanie endpointu.

Query parameter

/books?author=LeGuin&page=2

  • filtr, sortowanie lub stronicowanie,
  • często opcjonalny,
  • nie zmienia bazowej ścieżki zasobu.
14 // JSON DO OBIEKTU

@RequestBody uruchamia deserializację body

BookController.java
@PostMapping
ResponseEntity<BookResponse> create(
        @Valid @RequestBody CreateBookRequest request) {
    BookResponse created = service.create(request);
    URI location = URI.create("/api/books/" + created.id());
    return ResponseEntity.created(location).body(created);
}

Jackson tworzy rekord z JSON, Bean Validation sprawdza dane, a odpowiedź 201 zawiera nagłówek Location.

22 // WSPÓLNA OBSŁUGA

@RestControllerAdvice utrzymuje jednolity kontrakt błędów

ApiExceptionHandler.java
@RestControllerAdvice
class ApiExceptionHandler {
    @ExceptionHandler(BookNotFoundException.class)
    ResponseEntity<ProblemDetail> notFound(BookNotFoundException ex) {
        ProblemDetail problem = ProblemDetail.forStatusAndDetail(
            HttpStatus.NOT_FOUND, ex.getMessage());
        return ResponseEntity.status(404).body(problem);
    }
}
23 // SEMANTYKA ODPOWIEDZI

Status HTTP mówi klientowi, jaki jest wynik operacji

200 OK

Odczyt lub zmiana

Operacja zakończona, body zawiera reprezentację.

201 Created

Utworzenie

Nowy zasób i jego adres w nagłówku Location.

204 No Content

Bez reprezentacji

Operacja zakończona i nie ma body.

400 Bad Request

Złe dane

Format lub walidacja żądania nie przeszły.

404 Not Found

Brak zasobu

Identyfikator ma poprawny format, ale zasobu nie ma.

409 Conflict

Konflikt stanu

Żądanie koliduje z aktualnym stanem danych.
