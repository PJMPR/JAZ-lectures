PRZYKŁAD 00 // TEN SAM PROBLEM

Aktywne konta zapisane wielkimi literami

PĘTLA
List<String> result = new ArrayList<>();
for (User user : users) {
    if (user.active()) {
        result.add(user.name().toUpperCase());
    }
}
STRUMIEŃ
List<String> result = users.stream()
    .filter(User::active)
    .map(User::name)
    .map(String::toUpperCase)
    .toList();
Oba fragmenty dają ten sam wynik. Różnią się sposobem opisania pracy.
01 // MODEL

Strumień nie jest kolekcją

source

Źródło

Kolekcja, tablica, plik albo generator dostarcza elementy.

pipeline

Potok

Operacje opisują wybór, transformację i porządek danych.

result

Wynik

Operacja terminalna produkuje wartość lub efekt końcowy.

Ważne: strumień nie przechowuje danych i nie modyfikuje automatycznie kolekcji źródłowej.
PRZYKŁAD 01 // ANATOMIA POTOKU

Źródło, etapy, terminal

Orders.java
List<String> ids = orders.stream()  // źródło
    .filter(Order::paid)            // pośrednia
    .sorted(Comparator.comparing(Order::date))
    .map(Order::id)                 // pośrednia
    .toList();                      // terminalna
PRZEPŁYW

Typ może zmieniać się po drodze

  1. Źródło dostarcza Order.
  2. filter zachowuje typ elementu.
  3. map zmienia Order na String.
  4. toList materializuje wynik.
02 // LAZY EVALUATION

Bez terminala nic nie płynie

Operacje pośrednie budują przepis. Przetwarzanie rozpoczyna dopiero operacja terminalna.

Konsekwencja: samo wywołanie filter lub map nie wykonuje lambdy.
Stream<String> pipeline = names.stream()
    .filter(name -> {
        System.out.println(name);
        return name.length() > 3;
    });

// jeszcze nic nie wypisano
long count = pipeline.count();
PORÓWNANIE 01 // FILTER

Wybór elementów spełniających warunek

PĘTLA
List<Product> available = new ArrayList<>();
for (Product product : products) {
    if (product.stock() > 0) {
        available.add(product);
    }
}
STREAM API
List<Product> available = products.stream()
    .filter(product -> product.stock() > 0)
    .toList();
filter przyjmuje Predicate<Product> i przepuszcza tylko elementy z wynikiem true.
PORÓWNANIE 02 // MAP

Transformacja każdego elementu

PĘTLA
List<String> emails = new ArrayList<>();
for (User user : users) {
    emails.add(user.email().toLowerCase());
}
STREAM API
List<String> emails = users.stream()
    .map(User::email)
    .map(String::toLowerCase)
    .toList();
map przyjmuje Function<T,R>; liczba elementów zwykle pozostaje taka sama, ale zmienić może się ich typ.
PORÓWNANIE 03 // POTOK

Najpierw wybierz, potem przekształć

PĘTLA
List<String> labels = new ArrayList<>();
for (Product p : products) {
    if (p.price().compareTo(limit) <= 0) {
        labels.add(p.name().toUpperCase());
    }
}
STREAM API
List<String> labels = products.stream()
    .filter(p -> p.price().compareTo(limit) <= 0)
    .map(Product::name)
    .map(String::toUpperCase)
    .toList();
Kolejność etapów ma znaczenie: wcześniejszy filter ogranicza liczbę późniejszych transformacji.
03 // SORTED · DISTINCT · LIMIT

Porządkowanie i ograniczanie

List<String> topNames = users.stream()
    .map(User::name)
    .distinct()
    .sorted(Comparator.comparingInt(String::length)
        .thenComparing(Comparator.naturalOrder()))
    .limit(5)
    .toList();
distinct usuwa duplikatysorted porządkujelimit bierze początekskip pomija początek

distinct opiera się na equals i hashCode. sorted może wymagać buforowania wszystkich elementów.

PORÓWNANIE 04 // SORTOWANIE

Nowa lista bez zmiany źródła

KOLEKCJA I PĘTLA
List<Product> sorted = new ArrayList<>();
for (Product product : products) {
    sorted.add(product);
}
sorted.sort(Comparator.comparing(Product::price));
STREAM API
List<Product> sorted = products.stream()
    .sorted(Comparator.comparing(Product::price))
    .toList();
List.sort zmienia listę, na której jest wywołane. stream().sorted().toList() tworzy wynik i pozostawia źródło bez zmian.
PORÓWNANIE 05 // MATCH

Czy istnieje element spełniający warunek?

PĘTLA
boolean hasOverdue = false;
for (Invoice invoice : invoices) {
    if (invoice.overdue()) {
        hasOverdue = true;
        break;
    }
}
STREAM API
boolean hasOverdue = invoices.stream()
    .anyMatch(Invoice::overdue);
KRÓTKIE SPIĘCIE

anyMatch, allMatch, noneMatch i findFirst mogą zakończyć pracę przed końcem źródła.

PRZYKŁAD 06 // OPTIONAL

Wyszukiwanie może nie dać wyniku

Optional<User> admin = users.stream()
    .filter(User::admin)
    .findFirst();

String label = admin
    .map(User::name)
    .orElse("brak administratora");
KONTRAKT

Brak wartości jest jawny

  1. findFirst zwraca Optional<T>.
  2. map przekształca wartość, jeśli istnieje.
  3. orElse dostarcza wartość zastępczą.

Nie wywołuj get() bez sprawdzenia obecności.

PORÓWNANIE 06 // AGREGACJA

Suma wartości

PĘTLA
int total = 0;
for (Order order : orders) {
    if (order.paid()) {
        total += order.amount();
    }
}
STREAM API
int total = orders.stream()
    .filter(Order::paid)
    .mapToInt(Order::amount)
    .sum();
mapToInt tworzy IntStream, który oferuje sum, average, min i max bez autoboxingu.
04 // REDUCE

Wiele elementów → jedna wartość

Redukcja łączy kolejne elementy w akumulator. Operacja powinna być łączna i pozbawiona efektów ubocznych.

identity + accumulator → resultwartość początkowa i reguła łączenia
int sum = numbers.stream()
    .reduce(0, Integer::sum);

Optional<Integer> maximum = numbers.stream()
    .reduce(Integer::max);

String csv = names.stream()
    .collect(Collectors.joining(", "));
Praktyka: dla sumy typów liczbowych wybierz wyspecjalizowany strumień; do budowania kolekcji użyj kolektora, nie mutowalnego reduce.
PORÓWNANIE 07 // GROUPING BY

Grupowanie obiektów według cechy

PĘTLA
Map<Status, List<Order>> byStatus =
    new HashMap<>();
for (Order order : orders) {
    byStatus.computeIfAbsent(order.status(),
        key -> new ArrayList<>()).add(order);
}
STREAM API
Map<Status, List<Order>> byStatus =
    orders.stream().collect(
        Collectors.groupingBy(Order::status));
Kolektor zarządza tworzeniem kontenerów, dodawaniem elementów i łączeniem częściowych wyników.
05 // COLLECTORS

Gotowe strategie agregacji

groupingBy

Grupy

Map<K, List<T>> według wybranego klucza.

partitioningBy

Dwa zbiory

Podział na elementy spełniające i niespełniające warunku.

toMap

Mapa

Wymaga funkcji klucza, wartości, a czasem reguły kolizji.

Map<String, Long> countByCity = users.stream().collect(
    Collectors.groupingBy(User::city, Collectors.counting()));
PRZYKŁAD 08 // KOLEKTORY LICZBOWE

Suma, średnia, minimum i maksimum

OrderStatistics.java
int sum = orders.stream().collect(
    Collectors.summingInt(Order::amount));

double average = orders.stream().collect(
    Collectors.averagingInt(Order::amount));

Optional<Order> smallest = orders.stream().collect(
    Collectors.minBy(Comparator.comparingInt(Order::amount)));

Optional<Order> largest = orders.stream().collect(
    Collectors.maxBy(Comparator.comparingInt(Order::amount)));
TYPY WYNIKÓW

Wartość albo obiekt

  1. summingInt zwraca Integer.
  2. averagingInt zwraca Double.
  3. minBy i maxBy zwracają Optional<Order>.

Optional reprezentuje możliwość braku wyniku dla pustego strumienia.

PRZYKŁAD 09 // PODSUMOWANIE LICZBOWE

Wszystkie statystyki w jednym obiekcie

OrderSummary.java
IntSummaryStatistics stats = orders.stream()
    .collect(Collectors.summarizingInt(Order::amount));

long count = stats.getCount();
long sum = stats.getSum();
double average = stats.getAverage();
int minimum = stats.getMin();
int maximum = stats.getMax();
JEDEN PRZEBIEG

summarizingInt

Kolektor oblicza liczbę elementów, sumę, średnią, minimum i maksimum podczas jednego przejścia przez strumień.

int IntSummaryStatisticslong LongSummaryStatisticsdouble DoubleSummaryStatistics

Dostępne są również kolektory summarizingLong i summarizingDouble.

PORÓWNANIE 10 // FLATMAP

Spłaszczenie zagnieżdżonych kolekcji

DWIE PĘTLE
List<String> tags = new ArrayList<>();
for (Article article : articles) {
    for (String tag : article.tags()) {
        tags.add(tag);
    }
}
STREAM API
List<String> tags = articles.stream()
    .flatMap(article -> article.tags().stream())
    .toList();
map dałby Stream<List<String>>. flatMap łączy wewnętrzne strumienie w jeden Stream<String>.
06 // CYKL ŻYCIA

Strumień wykorzystujemy tylko raz

Stream<String> stream = names.stream();

long count = stream.count();

// IllegalStateException:
// stream.forEach(System.out::println);

Po wykonaniu terminala strumień jest zamknięty. Jeśli potrzebujesz drugiego przebiegu, utwórz nowy strumień ze źródła.

Zapamiętaj: kolekcję można przeglądać wielokrotnie; strumień reprezentuje pojedyncze przetwarzanie.
PUŁAPKA 01 // EFEKTY UBOCZNE

Nie przemycaj pętli do forEach

PROBLEMATYCZNE
List<String> result = new ArrayList<>();
users.stream()
    .filter(User::active)
    .forEach(user -> result.add(user.name()));
DEKLARATYWNIE
List<String> result = users.stream()
    .filter(User::active)
    .map(User::name)
    .toList();
Zewnętrzna mutacja utrudnia testowanie i staje się niebezpieczna przy przetwarzaniu równoległym.
07 // TO LIST

Stream.toList() zwraca listę niemodyfikowalną

List<String> names = users.stream()
    .map(User::name)
    .toList();

// names.add("Ada");
// UnsupportedOperationException

List<String> mutable = users.stream()
    .map(User::name)
    .collect(Collectors.toCollection(ArrayList::new));

Dobierz sposób zebrania wyniku do kontraktu. Niemodyfikowalna lista jest dobrym domyślnym wyborem, gdy wynik ma być tylko odczytywany.

Uwaga: niemodyfikowalna lista nie oznacza, że obiekty znajdujące się w niej są niemutowalne.
08 // PARALLEL STREAM

Równolegle nie znaczy automatycznie szybciej

dużo danych

Koszt pracy

Operacje muszą być na tyle kosztowne, by opłacił się podział pracy.

stateless

Brak współdzielenia

Lambdy nie powinny modyfikować wspólnego stanu.

measure

Pomiar

Decyzję podejmujemy na podstawie benchmarku, nie długości kodu.

long count = values.parallelStream().filter(this::expensiveTest).count();
Zasada Zacznij od zwykłego strumienia. Użyj równoległego dopiero dla mierzalnej korzyści i bezpiecznych operacji.
09 // DEBUGOWANIE

Nazwij złożone reguły, podglądaj ostrożnie

Predicate<Order> highValue =
    order -> order.total().compareTo(limit) > 0;

List<String> ids = orders.stream()
    .filter(highValue)
    .peek(order -> log.debug("Selected {}", order.id()))
    .map(Order::id)
    .toList();
CZYTELNOŚĆ

Potok ma opowiadać historię

  1. Nazwij regułę domenową.
  2. Łam potok na logiczne etapy.
  3. peek traktuj jako narzędzie diagnostyczne.
  4. Gdy pętla jest prostsza — użyj pętli.
10 // DOBÓR NARZĘDZIA

Stream API nie zastępuje każdej pętli

Wybierz strumień, gdy…

  • tworzysz wynik z sekwencji danych,
  • potok składa się z wyboru, transformacji i agregacji,
  • operacje są bezstanowe i łatwe do nazwania.

Wybierz pętlę, gdy…

  • algorytm ma złożony, zmienny stan,
  • potrzebujesz precyzyjnego sterowania przebiegiem,
  • wersja strumieniowa ukrywa intencję zamiast ją wyjaśniać.
CEL = czytelny kod, a nie maksymalna liczba wywołań stream()

PRZYKŁAD FINAŁOWY // REFAKTORYZACJA

Od zagnieżdżonych pętli do potoku

Set<String> result = new TreeSet<>();
for (Order order : orders) {
    if (order.paid()) {
        for (Item item : order.items()) {
            if (item.quantity() >= 2) {
                result.add(item.name());
            }
        }
    }
}
Set<String> result = orders.stream()
    .filter(Order::paid)
    .flatMap(order -> order.items().stream())
    .filter(item -> item.quantity() >= 2)
    .map(Item::name)
    .collect(Collectors.toCollection(TreeSet::new));
