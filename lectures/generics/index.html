public class Box<T> {

T typeE elementK keyV value

04 // BOUNDED TYPE PARAMETERS

Nie każdy typ pasuje do misji

Ograniczenie daje kompilatorowi gwarancję, że obiekt posiada określone metody.

<T extends Number>T musi być klasą Number lub jej podtypem
Ważne: słowa extends używamy także dla ograniczenia interfejsem.
Numbers.java
public static <T extends Number>
double doubleValue(T number) {
    return number.doubleValue();
}

doubleValue(Integer.valueOf(7)); // OK
doubleValue(Double.valueOf(2.5)); // OK
// doubleValue("7"); // nie skompiluje się

06 // WILDCARDS

Trzy poziomy dostępu

List<?>

Nieznany typ

Bezpiecznie odczytasz jako Object. Nie dodasz wartości poza null.

List<? extends Number>

Producent

Bezpiecznie odczytasz Number. Nie wiesz jednak, jaki dokładnie podtyp lista przyjmuje.

List<? super Integer>

Konsument

Bezpiecznie dodasz Integer. Odczyt ma jedynie gwarantowany typ Object.

Zapamiętaj Wildcard opisuje elastyczny typ argumentu, a nie nowy nazwany parametr typu.

07 // PECS PROTOCOL

Producer Extends, Consumer Super

Copy.java
public static <T> void copy(
        List<? extends T> source,
        List<? super T> destination) {

    for (T item : source) {
        destination.add(item);
    }
}
PRODUCER? extends Tźródło produkuje wartości T
TRANSFER →
CONSUMER? super Tcel konsumuje wartości T

PECS dotyczy roli parametru. Jeśli jednocześnie odczytujesz i zapisujesz, często potrzebujesz konkretnego List<T>.

09 // TYPE ERASURE

Po kompilacji parametr znika

01

Brak new T()

JVM nie zna konkretnego typu T. Fabrykę lub konstruktor trzeba przekazać jawnie.

02

Brak T.class

Informację o klasie można przekazać jako parametr Class<T>.

03

Brak typów prostych

Używamy Integer, nie int; Double, nie double.

Konsekwencja: w czasie działania zwykle nie odróżnisz List<String> od List<Integer>.
