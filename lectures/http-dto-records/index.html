01 // NOŚNIK DANYCH

Record deklaruje przejrzysty, płytko niemutowalny agregat danych

User.java
public record User(
    String name,
    String email
) {}
KOMPILATOR DODAJE

Stan bez boilerplate'u

Konstruktor kanoniczny, akcesory name() i email(), a także equals, hashCode i toString.

02 // WAŻNE OGRANICZENIA

Finalne pola nie gwarantują głębokiej niemutowalności

final

Referencja

Komponentu rekordu nie można przypisać ponownie po konstrukcji.

mutable

Obiekt wewnątrz

Lista przekazana do rekordu nadal może być modyfikowalna.

copyOf

Kopia obronna

List.copyOf zabezpiecza kolekcję w konstruktorze kompaktowym.

Precyzja: record jest płytko niemutowalny, a nie automatycznie „w pełni immutable”.
03 // INWARIANT

Konstruktor kompaktowy może walidować i normalizować dane

RandomUserResponse.java
public record RandomUserResponse(
        List<UserDto> results,
        PageInfoDto info) {

    public RandomUserResponse {
        results = List.copyOf(results);
    }
}
KOPIA OBRONNA

Lista staje się niemodyfikowalna

Przypisanie do parametrów konstruktora następuje przed automatycznym zapisaniem komponentów rekordu.

04 // WZORZEC

DTO opisuje dane przekraczające granicę

Data Transfer Object przenosi dane pomiędzy procesami, warstwami lub publicznymi kontraktami. Nie powinien przejmować reguł biznesowych encji.

  • odzwierciedla kontrakt wejścia lub wyjścia,
  • ogranicza ujawniane pola,
  • izoluje domenę od zmian zewnętrznego API.
Record ≠ DTO: record jest konstrukcją języka, DTO jest rolą architektoniczną. Record często dobrze pełni tę rolę.

UserDto.java
public record NameDto(
    String title, String first, String last) {}

public record UserDto(
    NameDto name, String email, String nat) {
    public String fullName() {
        return name.first() + " " + name.last();
    }

JACKSON

Nazwy zgodne — zero adnotacji

Jeżeli komponent rekordu ma tę samą nazwę co pole JSON, Jackson dopasuje go konwencją.

08 // RÓŻNE NAZWY

@JsonProperty tłumaczy kontrakt JSON na język modelu

PageInfoDto.java
public record PageInfoDto(
    String seed,
    @JsonProperty("results") int resultCount,
    int page,
    String version
) {}
LOKALNA DECYZJA

Czytelna nazwa w Javie

Adnotację stosuj tam, gdzie kontrakt naprawdę różni się od modelu. Nie dekoruj każdego pola bez potrzeby.

09 // NARZĘDZIA

Adnotacje rozwiązują konkretne różnice kontraktu

@JsonProperty

Nazwa

Łączy inną nazwę pola JSON z komponentem Javy.

@JsonIgnoreProperties

Nadmiarowe pola

Może jawnie tolerować nieznane elementy odpowiedzi.

@JsonFormat

Format

Opisuje niestandardową reprezentację daty lub liczby.

Nie myl kierunków: odczyt JSON to deserializacja, zapis obiektu do JSON to serializacja.
10 // POZA KODEM

application.properties

randomuser.results=${RANDOMUSER_RESULTS:2}

PLACEHOLDER

Zmienna albo wartość domyślna

11 // TYPOWANA KONFIGURACJA

Grupa ustawień staje się jednym walidowanym obiektem

RandomUserProperties.java
@Validated
@ConfigurationProperties("randomuser")
public record RandomUserProperties(
    URI baseUrl,
    @Min(1) @Max(100) int results,
    @NotBlank String nationality,
    @NotBlank String seed) {}
FAIL FAST

Błąd przy starcie

Typy i walidacja zatrzymują aplikację, zanim niepoprawna konfiguracja dotrze do żądania HTTP.

12 // WYBÓR NARZĘDZIA

@Value dla pojedynczej wartości, @ConfigurationProperties dla kontraktu

@Value

  • szybki dostęp do jednej właściwości,
  • zależność rozproszona po beanach,
  • ograniczone relaxed binding i brak metadanych.

@ConfigurationProperties

  • spójna grupa ustawień,
  • konwersja do URI, liczb i innych typów,
  • walidacja oraz wsparcie IDE.
13 // NIE SKLEJAJ STRINGÓW

Parametry zapytania mają własne reguły kodowania

kruchy zapis
String url = base + "/api?seed=" + seed
    + "&results=" + count;
PROBLEMY

Spacje, znaki specjalne i separatory

Ręczna konkatenacja miesza strukturę URI z danymi i łatwo generuje niepoprawne albo niebezpieczne adresy.

14 // STRUKTURALNE URI

UriComponentsBuilder rozdziela segmenty i parametry

RandomUserClient.java
URI uri = UriComponentsBuilder
    .fromUri(properties.baseUrl())
    .pathSegment("api", "1.4")
    .queryParam("results", properties.results())
    .queryParam("nat", properties.nationality())
    .queryParam("seed", properties.seed())
    .build().encode().toUri();
Kolejność ma znaczenie: najpierw podstawiamy wartości, potem kodujemy gotowe komponenty URI.

16 // SYNCHRONICZNY KLIENT

RestClient opisuje żądanie płynnym API i mapuje body

RandomUserClient.java
public RandomUserResponse fetchUsers() {
    URI uri = buildUri();
    return http.get()
        .uri(uri)
        .retrieve()
        .body(RandomUserResponse.class);
}
SYNCHRONICZNIE

Wątek czeka na odpowiedź

retrieve() obsługuje odpowiedź, a body(...) uruchamia konwersję JSON do wskazanego DTO.

17 // FLUENT API

Każdy etap żądania ma własną odpowiedzialność

get / post

Metoda

Wybór operacji HTTP rozpoczyna budowanie żądania.

uri + headers

Żądanie

Adres, nagłówki i opcjonalne body opisują dane wysyłane do API.

retrieve

Odpowiedź

body, toEntity lub obsługa statusu kończą wywołanie.

Czytelność: kod ma tę samą kolejność, co żądanie HTTP — metoda, URI, odpowiedź i jej reprezentacja.
18 // BEAN WSPÓŁDZIELONY

Spring Boot dostarcza skonfigurowany prototyp RestClient.Builder

HttpClientConfiguration.java
@Bean
RestClient restClient(RestClient.Builder builder) {
    return builder
        .requestFactory(requestFactory())
        .build();
}

Wstrzykiwany builder zachowuje auto-konfigurację Spring Boot, a gotowy klient jest bezpieczny do współdzielenia między wątkami.

19 // ŚCIEŻKI NEGATYWNE

Błąd transportu to nie to samo co błąd kontraktu

4xx / 5xx

Status HTTP

Domyślnie wyjątek klienta lub serwera HTTP.

timeout

Transport

Brak połączenia lub odpowiedzi w oczekiwanym czasie.

JSON

Mapowanie

Odpowiedź nie pasuje do oczekiwanego DTO.

Na granicy: przetłumacz wyjątek infrastruktury na błąd zrozumiały dla własnej aplikacji i zachowaj przyczynę.
20 // KLIENT PRODUKCYJNY

Każde zewnętrzne wywołanie potrzebuje limitu czasu

HttpClientConfiguration.java
var jdkClient = HttpClient.newBuilder()
    .connectTimeout(Duration.ofSeconds(2))
    .build();
var factory = new JdkClientHttpRequestFactory(jdkClient);
factory.setReadTimeout(Duration.ofSeconds(3));
OGRANICZ OCZEKIWANIE

Sieć może nie odpowiedzieć

Timeout nie naprawia awarii, ale chroni pulę wątków i umożliwia kontrolowaną reakcję systemu.
